# Linux 部署模板

本目录提供可审查的运行模板，未关联实际主机或域名，也未执行公网部署。

## 构建

在已有素材包的工作副本中执行 `npm ci`、`npm run build`，确认应用测试通过后构建 Docker 镜像。Docker 构建读取已生成的 `public/game/`，不把素材包、账号数据库、配置或开发工具打进镜像。

部署侧采用游戏服务和 LiveKit 两个进程，SQLite 与账号数据通过独立目录持久化。复制 Compose 和 LiveKit 示例到选定部署目录，创建私有 `config.yaml`，其中游戏 `server.host` 设为容器内 `0.0.0.0`；数据库路径使用 `data/game.sqlite`。

语音浏览器地址设置为实际 `wss://` 入口，服务端管理地址可用 `http://voice:7880`。LiveKit 和应用中的 API 密钥必须一致。生产配置需要自行生成随机凭据，不能使用示例占位值。

## 对外入口

网页和 Colyseus 需要 HTTPS/WSS，语音信令通过独立可达的 WSS 入口。HTTP 反向代理需支持 WebSocket 升级，媒体 UDP/TCP 必须独立可达；网页能访问不能替代语音测试。

示例提供 WebRTC UDP mux 和 TCP 回退。严格网络环境需要另外配置 TURN/TLS、证书及对应入口后再验收；当前示例没有虚构可用 TURN 域名。接入既有中央反向代理时按目标主机约定设置网络和服务发现，不直接套用本地回环映射。

数据目录需允许镜像内 `node` 用户写入，配置只读挂载。部署后依次核验健康接口、两个独立用户登录、邀请/准备/开局、真实语音、手机 HTTPS 访问及服务重启后的身份恢复。

首次公网部署前还需要明确部署地区、并发目标和实际地址。Windows 自带 LiveKit 仅作本地联调；其 CPU 容量监测不支持当前 Windows 平台，生产使用 Linux 模板。
